# TOKENA - Bun Setup & Package Management

## Overview

This project uses **Bun** (v1.0+) as the primary package manager and runtime. Bun is a fast, all-in-one JavaScript runtime and package manager that serves as a drop-in replacement for Node.js.

---

## What is Bun?

**Bun** is a modern JavaScript runtime with:

### Key Features
- **Ultra-fast startup**: 10-100x faster than Node.js
- **Integrated package manager**: No need for npm, yarn, or pnpm
- **Native TypeScript support**: Run TypeScript files directly
- **Bundler included**: Built-in code bundling
- **Test runner**: Native testing without Jest setup
- **Script runner**: Execute scripts from package.json
- **ES modules native**: Full ESM support

### Performance Metrics (Bun vs npm)
| Operation | npm | Bun | Improvement |
|-----------|-----|-----|-------------|
| Install dependencies | ~45s | ~2-5s | 10-20x faster |
| Run dev server | ~8s startup | ~1-2s startup | 4-8x faster |
| Build TypeScript | Varies | ~0.5-2s | 5-10x faster |

## Installation

### Prerequisites
- Windows 10+ or Mac OS 10.13+ or Linux

#### Linux
```bash
curl -fsSL https://bun.sh/install | bash
```

## Project Setup with Bun

### Initialize Project
```bash
# Project already has bun.lockb
# Just install dependencies
bun install

# Or in directory
cd d:\Proyecto\tokena

```

### Lock File (`bun.lockb`)
- Binary format lock file generated by Bun
- Ensures consistent dependencies across environments
- Smaller than package-lock.json (~400KB vs ~2MB)
- Faster to parse and install

## Package.json Scripts

### Current Scripts

```json
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "lint": "eslint .",
    "preview": "vite preview"
  }
}
```

### Breakdown

#### `dev` - Development Server
```bash
bun run dev
```
- Starts Vite development server
- Listens on port 5173
- Hot Module Replacement (HMR) enabled
- TypeScript compiled on-the-fly

#### `build` - Production Build
```bash
bun run build
```
- Step 1: `tsc -b` - TypeScript compilation
  - Checks type errors
  - Validates entire codebase
  - Does NOT emit files (--noEmit could be added)

- Step 2: `vite build` - Production bundling
  - Minifies code
  - Optimizes assets
  - Creates dist/ folder
  - Generates source maps (optional)

**Output**:
```
dist/
├── index.html
├── assets/
│   ├── app-[hash].js
│   ├── vendor-[hash].js
│   └── style-[hash].css
└── manifest.json
```

#### `lint` - Code Quality Check
```bash
bun run lint
```
- Runs ESLint on all files
- Checks TypeScript syntax
- Validates React best practices
- No auto-fix (add --fix flag to auto-correct)

```bash
# Auto-fix linting issues
bun run lint -- --fix
```

#### `preview` - Production Preview
```bash
bun run preview
```
- Serves optimized production build
- Tests build in local environment
- Useful before deployment

### Dependency Versions

**Caret (^)**: Allows minor and patch updates
```
^19.1.1 means >=19.1.1 <20.0.0
```

**Tilde (~)**: Allows only patch updates
```
~5.9.3 means >=5.9.3 <5.10.0
```

**Exact**: No updates
```
2.15.4 means exactly 2.15.4
```

## Build Process Details

### TypeScript Compilation

#### Configuration (`tsconfig.json`)
```json
{
  "compilerOptions": {
    "target": "ES2020",                 // Target JavaScript version
    "module": "ESNext",                 // Module system
    "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "jsx": "react-jsx",                 // JSX compilation
    "strict": true,                     // Enable strict mode
    "esModuleInterop": true,            // ES module interop
    "moduleResolution": "bundler",      // Module resolution
    "allowImportingTsExtensions": true, // Import TS files
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]                  // Path alias
    }
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

### Vite Configuration (`vite.config.ts`)
```typescript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import path from 'path'

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
    },
  },
  server: {
    port: 5173,
    host: true,  // Listen on all IPs
  },
  build: {
    target: 'ES2020',
    minify: 'terser',
    sourcemap: false,  // Disable in production
    rollupOptions: {
      output: {
        manualChunks: {
          'react': ['react', 'react-dom'],
          'ui': ['@radix-ui/react-*'],
        }
      }
    }
  }
})
```

### Build Optimization Steps

#### 1. Code Splitting
- React and ReactDOM in separate bundle
- UI components grouped together
- Lazy-loaded route components

#### 2. Tree Shaking
- Removes unused code
- Follows ES module import/export
- Works with libraries supporting ESM

#### 3. Minification
- Removes whitespace and comments
- Shortens variable names
- ~60-70% size reduction

#### 4. Asset Optimization
- Image compression (future)
- CSS purging (Tailwind)
- Font optimization

## Troubleshooting

### Issue: "bun: command not found"
**Solution**: Add Bun to PATH or reinstall
```bash
# Check installation
bun --version

# Reinstall
curl -fsSL https://bun.sh/install | bash
source ~/.bashrc  # or ~/.zshrc for zsh
```

### Issue: Dependency conflicts
**Solution**: Clear cache and reinstall
```bash
# Remove lock file
rm bun.lockb

# Clear cache
bun pm cache clear

# Reinstall
bun install
```

### Issue: Port 5173 already in use
**Solution**: Change port in vite.config.ts
```bash
# Or specify port in command
bun run dev -- --port 3000
```

### Issue: TypeScript errors after installation
**Solution**: Rebuild TypeScript cache
```bash
bun run build
```

### Issue: Module not found errors
**Solution**: Check path aliases in tsconfig.json
```typescript
// Ensure @/ points to src/
"paths": { "@/*": ["src/*"] }
```

## Best Practices

### 1. Use Bun for All Scripts
```bash
# ✅ Good - Use bun for everything
bun install
bun run dev
bun run build

# ❌ Avoid - Mixing npm and bun
npm install  # Don't do this
bun run dev  # Stick to bun
```

### 2. Regular Dependency Updates
```bash
# Monthly dependency check
bun outdated

# Update non-breaking versions
bun update

# Test after updates
bun run build
bun run lint
```

### 3. Security Audits
```bash
# Check for vulnerabilities
bun audit

# Fix security issues
bun update  # Updates vulnerable packages
```

### 4. Keep Lock File in Version Control
```bash
# Always commit bun.lockb
git add bun.lockb
git commit -m "chore: update dependencies"
```

### 5. Version Consistency
```bash
# All developers should use same Bun version
bun --version

# Update Bun
bun upgrade
```
